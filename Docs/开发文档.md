# LongV AI 短剧导演台开发文档

> 当前版本按“每个镜头独立资产包”运行：角色、场景、分镜和视频输出都会保存实体或 `shotId`，视频镜头只读取自己的分镜关键帧，并保留上一镜头的结束帧/latent 上下文。

## 1. 项目目标

LongV 是一个本地运行的 AI 短剧生产工作台：用户输入一句故事，系统按阶段调用本地 ComfyUI，完成剧本、角色、环境、分镜、视频和后期素材准备。

目标流程：

```text
一句话故事
  ↓
剧本工作流
  ↓
角色参考图
  ↓
环境母图
  ↓
分镜图
  ↓
H3 分段视频
  ↓
剪辑、配音、字幕、发布
```

项目目录：

```text
D:\Demo\kitt\LongV
```

## 2. 技术结构

项目不依赖 Express、React 或数据库，当前使用 Node.js 原生 HTTP 服务，便于在本地 GPU 电脑上快速部署和修改。

```text
LongV/
├─ server.mjs              后端 HTTP 服务和 ComfyUI API 调用
├─ package.json            启动脚本
├─ README.md               简要说明
├─ 开发文档.md             本文档
├─ public/
│  ├─ index.html           页面结构
│  ├─ app.js               前端交互和 API 调用
│  ├─ styles.css           主样式
│  └─ overrides.css        补充样式
└─ data/
   ├─ settings.json        全局工作流库和默认配置
   └─ projects/
      ├─ <project-id>.json  项目状态
      └─ <project-id>/      项目生成的图片、视频和文本
```

## 3. 本地启动

要求：

- Node.js 18 或更高版本；
- ComfyUI 已安装并可以独立运行；
- ComfyUI API 默认地址为 `http://127.0.0.1:8188`。

启动 LongV：

```powershell
cd D:\Demo\kitt\LongV
npm start
```

浏览器访问：

```text
http://127.0.0.1:3030
```

如果 3030 已被占用，服务会自动顺延到 3031、3032 等端口，并在终端打印实际地址。

## 4. ComfyUI 工作流要求

必须导入 **API 格式 workflow JSON**，不是普通的画布工作流 JSON。

在 ComfyUI 中应使用“保存 API 格式”或对应的 API 工作流导出功能。

LongV 当前通过以下接口调用 ComfyUI：

```text
POST /prompt
GET  /history/{prompt_id}
GET  /view?filename=...&subfolder=...&type=...
POST /upload/image
```

### 工作流节点配置

前台导入 JSON 后会自动扫描节点，用户可以从下拉框选择：

- 正向提示词节点；
- 正向提示词字段；
- 负向提示词节点；
- 负向提示词字段；
- 输入图片节点；
- 输入图片字段。

工作流也支持以下占位符：

```text
{{prompt}}
{{image}}
{{width}}
{{height}}
{{frames}}
```

## 5. 工作流配置方式

工作流文件库是全局可复用的，但工作流绑定是项目级的。

推荐配置：

```text
AI编剧       → 剧本
角色设定图   → 角色
环境图       → 环境
分镜关键帧   → 分镜
H3图生视频   → 视频
```

操作步骤：

1. 先新建并选中一个项目；
2. 点击右上角“连接设置”；
3. 填写工作流名称；
4. 选择绑定阶段；
5. 导入 API 格式 JSON；
6. 从下拉框选择节点；
7. 保存。

项目会保存自己的：

```json
{
  "workflowSettings": {
    "comfyUrl": "http://127.0.0.1:8188",
    "bindings": {
      "script": "AI编剧",
      "environments": "环境图",
      "storyboard": "分镜关键帧",
      "video": "H3图生视频"
    }
  }
}
```

因此不同项目可以使用不同的工作流组合和不同的 ComfyUI 地址。

## 6. 阶段数据传递

### 6.1 剧本文本

剧本阶段先生成本地基础分镜计划。如果绑定了剧本 ComfyUI 工作流，系统会调用它；如果返回标准文本输出，系统会保存为 `project.scriptText`，并把它带入角色、环境、分镜和视频提示词。

当前阶段输出可能包括：

```text
story-plan.json
script.txt
```

### 6.2 图片资产

图片输出会保存到：

```text
data/projects/<project-id>/<stage>/
```

当前传递关系：

```text
角色资产 + 场景资产 → 对应镜头分镜工作流
对应镜头分镜图 → 对应镜头视频工作流
```

传递过程：

1. 找到上一阶段的图片文件；
2. 调用 ComfyUI `/upload/image`；
3. 获取 ComfyUI 中的文件名；
4. 写入下一阶段工作流配置的图片节点；
5. 提交下一阶段 `/prompt`。

分镜和 H3 视频工作流必须配置 `LoadImage` 或兼容图片输入节点，否则图片不会注入。

每个角色和场景会单独执行一次工作流，并保存为带有 `entityId` 的资产记录；分镜会按 `shotId` 逐镜头执行，并保存为带有 `shotId` 的关键帧记录。视频生成时优先查找同一个 `shotId` 的分镜图，避免所有镜头重复使用第一张图。

### 6.3 视频镜头

视频阶段支持批量镜头。每个镜头默认使用：

```text
5 秒左右
单批次
上一阶段分镜图作为输入
```

视频工作流输出会保存到项目的视频阶段目录，并在前台显示。

## 7. 当前使用建议

第一次调试建议不要直接运行全部流程，按下面顺序检查：

```text
环境图 → 确认有图片
分镜图 → 确认收到了环境图
视频单镜头 → 确认 H3 能运行
视频全部镜头 → 确认分批生成
```

推荐先使用：

```text
576×1024 或工作流默认分辨率
3～5 秒
batch size = 1
先关闭高清放大、补帧、复杂音频
```

确认流程成功后，再提高分辨率、时长和采样步数。

## 8. 前四项已实现：进度、JSON、latent、合成

### 8.1 实时进度与单镜头重试

点击阶段按钮后，接口立即返回 `202` 和 `jobId`，前端每 1.2 秒读取项目状态，因此可以看到当前阶段和当前镜头。视频阶段会记录每个镜头的 `running/done/error` 状态，失败镜头旁会出现“重试”按钮；“全部镜头”会从头批量执行并清空旧的视频输出。

### 8.2 剧本 JSON 自动解析

如果剧本工作流输出文本，服务器会尝试解析 JSON，兼容 `shots`、`scenes`、`storyboard` 三种数组字段，并转换为 LongV 的统一镜头结构。建议剧本工作流输出如下格式：

```json
{"title":"短剧标题","logline":"一句话梗概","shots":[{"title":"开场","action":"人物走进雨夜","duration":5,"prompt":"电影感镜头提示词"}]}
```

解析后的文本保存为 `project.scriptText`，标准化结果保存到 `project.plan`。

### 8.3 跨镜头 latent / 上下文传递

每个视频镜头执行前会把以下占位符替换到 API workflow 的任意字符串字段中：

```text
{{previous_latent_id}}  {{current_latent_id}}
{{previous_frame}}      {{previous_video}}
{{shot_index}}          {{total_shots}}
```

状态保存在项目 JSON 的 `sequence` 和 `stages.video.shots` 中。服务器会从 ComfyUI history 中递归查找包含 `latent_id` 或 `current_latent` 的字段；如果 H3 没有返回标准 latent 字段，则使用 LongV 的连续运行 ID 作为逻辑接力标记。

如果视频工作流没有输出图片，服务器会在配置的 FFmpeg 可用时自动从视频末帧生成 `*-last.png`，作为下一个镜头的 `previous_frame`。要实现 H3 真正的 latent 接力，仍需把这些占位符放进 H3 工作流对应节点，并确认该 H3 自定义节点实际接受的字段名称。LongV 不会猜测不同 H3 版本的私有节点参数。

### 8.4 FFmpeg 自动合成

编辑阶段会按镜头编号生成 `edit/concat.txt`，调用 FFmpeg 合并视频；如果直接复制流失败，会自动转码为 H.264/AAC 的 MP4。连接设置中可以为当前项目填写 FFmpeg 可执行文件路径，例如：

```text
C:\\ffmpeg\\bin\\ffmpeg.exe
```

如果电脑已把 `ffmpeg` 加入 PATH，可以留空。当前开发环境未检测到 FFmpeg，回家调试时需要安装 FFmpeg 或填写绝对路径。

## 9. latent ID / 跨镜头上下文说明

当前版本已经支持提示词、图片资产和逻辑上下文传递。由于不同 H3 节点的真实字段不统一，仍需按实际工作流配置：

```text
previous_latent_id
current_latent_id
previous_frame
previous_video
shot_index
total_shots
```

如果 H3 工作流要求上一段的 latent ID，后续应增加“工作流参数适配层”。

### 建议的数据结构

```json
{
  "sequence": {
    "currentShot": 2,
    "previousLatentId": "latent_001",
    "currentLatentId": "latent_002",
    "previousFrame": "shot-001-last.png",
    "previousVideo": "shot-001.mp4"
  }
}
```

### 建议的输入映射

```json
{
  "inputs": {
    "prompt": ["42", "text"],
    "image": ["18", "image"],
    "previousLatentId": ["65", "previous_latent_id"],
    "currentLatentId": ["65", "current_latent_id"],
    "shotIndex": ["65", "shot_index"],
    "totalShots": ["65", "total_shots"]
  },
  "outputs": {
    "latentId": ["80", "latent_id"],
    "lastFrame": ["81", "image"]
  }
}
```

### 分镜循环逻辑

```text
previousLatentId = 空

for each shot:
    把 previousLatentId 写入当前工作流
    把 shotIndex 写入当前工作流
    提交 ComfyUI
    从 history 输出提取 currentLatentId
    previousLatentId = currentLatentId
```

注意：标准 ComfyUI 不一定会返回名为 `latent_id` 的字符串。必须查看 H3 自定义节点的实际输出格式，可能是文本、字符串、对象或节点内部上下文。调试时重点查看：

```text
GET /history/{prompt_id}
```

以及 H3 工作流中负责“段间引导/latent 接力”的节点。

## 11. 常见问题排查

### 连接设置打不开

按 `Ctrl + F5` 强制刷新。如果仍有问题，在浏览器开发者工具 Console 查看 JavaScript 报错。

### 端口被占用

程序会自动换端口。终端会打印：

```text
LongV Studio running at http://127.0.0.1:xxxx
```

### ComfyUI 找不到模型

这是 ComfyUI 工作流自身的模型路径问题。先单独在 ComfyUI 中打开 API 对应的工作流，确认它可以运行，再接入 LongV。

### 传图失败

检查：

1. ComfyUI 地址是否正确；
2. 工作流是否配置了输入图片节点；
3. 节点字段是否是 `image` 或工作流实际使用的字段；
4. 上一阶段是否真的生成了 png/jpg/webp 文件。

### 16GB 显存 OOM

先降低：

```text
分辨率
帧数
批量大小
采样步数
```

同时关闭浏览器中的其他 GPU 应用，启用 ComfyUI low-VRAM、CPU offload 或 tiled VAE。

## 12. 回家调试建议

到有 GPU 的电脑后，建议先做这四件事：

1. 用 ComfyUI 单独跑通 H3 API 工作流；
2. 保存一份可以成功运行的 API JSON；
3. 确认视频工作流的 `LoadImage` 节点和段间 latent 节点；
4. 再用 LongV 先跑“环境图 → 分镜图 → 单个视频镜头”。

不要一开始就测试整部短剧。先保证单个镜头成功，再测试多个镜头和 latent 接力。

## 13. 稳定性保护

当前版本增加了以下保护：

- 服务重启时，未完成的 `running` 阶段会自动标记为中断，可重新执行；
- ComfyUI 请求有超时，不会无限等待；
- 导入工作流时会检查是否为 API 格式对象；
- 同一个阶段正在运行时，重复点击会被拒绝；
- 视频没有自己的分镜输出时不会直接开跑，会提示先完成分镜；
- 合成没有视频镜头时不会调用 FFmpeg；
- 项目文件下载接口会阻止越权路径；
- `/api/health` 可用于检查当前 ComfyUI 是否在线。

建议回家后的第一步：

```powershell
Invoke-RestMethod http://127.0.0.1:8188/system_stats
Invoke-RestMethod http://127.0.0.1:3030/api/health
```

第二条命令的端口以 LongV 启动时终端打印的实际端口为准。

## 14. 运行日志

项目页面底部有 DOS 风格的“运行日志”窗口，会实时显示：

- 阶段开始和完成；
- 当前角色、场景或镜头；
- 使用的工作流名称；
- ComfyUI `prompt_id`；
- 输入图片和输出文件数量；
- ComfyUI 错误、连接超时和 FFmpeg 错误。

日志会保存到：

```text
data/projects/<project-id>.runtime.log
```

遇到问题时，先暂停日志滚动，再点击“复制日志”，把完整内容发来即可。也可以访问：

```text
GET /api/projects/<project-id>/logs?tail=500
```

## 15. 任务控制和排错

连接设置中可以点击“测试 ComfyUI 连接”。生成过程中，日志区提供“停止当前任务”；视频阶段失败后，可以点击“继续未完成”，系统只生成尚未完成或失败的镜头，不重复已经完成的镜头。

镜头数据也支持通过接口修改：

```text
PATCH /api/projects/<project-id>/shots/<shot-id>
```

可修改标题、动作、提示词、时长、机位、对白、角色和场景绑定。修改后只需要重跑对应镜头。

## 16. 可勾选后期工序

主流程完成视频合成后，页面会显示后期工序卡片，可以按需要勾选并执行：

```text
配音       → 需要绑定 voice 工作流
字幕       → LongV 本地生成 SRT，不需要 ComfyUI
音乐音效   → 需要绑定 music 工作流
发布导出   → FFmpeg 输出 1080×1920、H.264/AAC MP4
```

配音和音乐音效使用 ComfyUI 工作流，连接设置中的阶段绑定需要选择“配音”或“音乐音效”。字幕会优先使用剧本 JSON 中每个镜头的 `dialogue` / `subtitle` 字段，没有对白时使用镜头动作作为可编辑的字幕草稿。

工作流导入设置增加了输出节点映射，可指定：

```text
文本/剧本输出节点
图片输出节点
视频输出节点
末帧输出节点
latent 输出节点
```

不指定时仍会自动识别。指定后，LongV 会在结果文件上保存 `nodeId` 和 `outputKind`，减少多输出节点工作流拿错结果的情况。

## 17. 固定端口和快捷启动

LongV 固定使用：

```text
http://127.0.0.1:3030
```

不要再自动递增端口。如果 3030 被占用，启动窗口会直接提示端口冲突。

双击项目目录中的：

```text
启动.bat
```

它会启动 LongV 并自动打开浏览器。关闭时运行：

```text
停止.bat
```
